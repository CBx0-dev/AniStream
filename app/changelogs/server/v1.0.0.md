# v1.0.0 - Initial Release

First release of the AniStream Server, the self-hosted backend for the new Client/Server mode. It stores profiles, watch
history and catalog metadata centrally, keeps the AniWorld and S.TO catalogs up to date in the background and lets
multiple AniStream Clients share the same data.

## Current features

### API

- REST API built with ASP.NET Core on .NET 9, including an interactive API reference (OpenAPI and Scalar).
- Per-provider catalog for AniWorld and S.TO: series, seasons, episodes, genres, search and genre filtering.
- Watchlist, watch progress and custom lists for every profile.
- Multi-user profiles with Argon2 hashed passwords and cookie based sign-in.
- Two permission flags per profile: dashboard access and client access.
- An initial `root` account is created on the first startup, so you can sign in to the dashboard right away.
- Serves the latest client release to the updater of the desktop clients.
- Announces the client versions it is compatible with, so incompatible clients are detected on connect.

### Background worker

- Runs as a separate service and keeps the catalogs up to date, even while no one is watching.
- Separate workers for catalog sync, series sync and provider sync, which pick up queued jobs automatically.
- Automatic catalog sync every night at midnight UTC.
- Reuses the provider logic of the desktop apps through a bundled sidecar executable.
- Clients and the dashboard can request syncs, and failed jobs keep their error message for later inspection.

### Web dashboard

- Overview with total profiles, total series, jobs of the day and the success rate of the day.
- Notice when a newer server release is available, with a link to its release notes.
- Manual catalog sync.
- Audit log of all sync jobs with filters, pagination and error details.
- User profile management: create, edit and delete profiles, set dashboard and client access, avatar, theme and
  language.

### Storage and deployment

- SQLite storage with one profile database and one metadata database per provider. Schema migrations are applied
  automatically.
- Container images on GitHub Container Registry: `anistream-api` and `anistream-worker`.
- Docker Compose setup and a CapRover one-click template.
